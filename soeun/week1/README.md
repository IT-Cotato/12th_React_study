클래스 컴포넌트

- Render 메서드를 사용하여 JSX 요소를 반환해야 함
- extends 키워드로 React의 컴포넌트 클래스 상속
- 문법이 더 복잡하고 가독성이 떨어지는 단점 존재
- Hooks 등장 이후 함수형 컴포넌트만 사용하는 것이 일반적

함수형 컴포넌트

- App.tsx 파일은 함수 형태로 이루어졌으며 이렇게 함수 형태로 작성된 코드를 컴포넌트라고 함
  ![image.png](attachment:79246231-f957-4883-a260-a7061f355e75:image.png)
- 조건
  - 함수로 작성되어야 함
  - return으로 JSX 요소나 null 반환
    - undefined도 안됨
    - null값 반환은 아무것도 렌더링하지 않는다는 의미
    - JSX 반환은 해당 요소를 화면에 렌더링한다는 의미
- 컴포넌트가 있는 tsx 파일을 컴포넌트라고 부르기 때문에 app.tsx는 App.componant

React.Fragment

- JSX는 반드시 하나의 루트 요소를 반환해야 함
- 두 개인 경우 `<div>` 태그로 그루핑을 해야 함
- 이 때 `<div>` 태그도 화면에 렌더링 됨
- 리액트의 Fragment 컴포넌트는 화면에 렌더링되지 않으면서 단순히 묶기 위한 것
  ```python
  <React.Fragment>
  	<h1>1</h1>
  	<h1>1</h1>
  </React.Fragment>
  ```
  ```python
  <>
  	<h1>1</h1>
  	<h1>1</h1>
  </>
  ```

컴포넌트 트리

- 컴포넌트들이 계층적으로 구성된 구조
- 리액트 애플리케이션 실행을 위해서는 반드시 하나의 루트 컴포넌트가 존재해야 함
- 루트 컴포넌트를 중심으로 여러 개의 컴포넌트가 연결되면서 화면이 구성됨
- App.tsx가 루트 컴포넌트의 역할. 다른 컴포넌트들을 연결해야 함

루트 컴포넌트

- main.tsx에서는 createRoot 함수를 사용해 id가 루트인 요소를 루트 컨테이너로 생성한 후 render 함수를 통해 앱 컴포넌트를 렌더링 함
- 앱 컴포넌트가 실제 UI를 렌더링하는 역할을 담당하므로 React 애플리케이션의 루트 컴포넌트라고 부름
- Strict Mode는 개발 모드의 잠재적 문제를 감지하기 위한 래퍼 컴포넌트
  - 래퍼 컴포넌트는 실제 UI를 렌더링하는 역할은 아니기에 루트 컴포넌트를 가리킬 때 래퍼 컴포넌트는 포함하지 않고 실제 UI를 렌더링하는 앱 컴포넌트를 루트 컴포넌트라고 함
  - StrictMode는 앱 컴포넌트 외 다른 컴포넌트를 배치해 여러 개를 렌더링 할 수 있음
  - 하지만 하나의 최상위 컴포넌트만을 두는 것이 바람직함
