### 데이터 패칭 기초 개념

`리액트에서의 데이터 통신`
컴포넌트가 서버에 외부 데이터를 요청하고, 그 응답을 받아 상태로 반영하여 UI를 업데이트 하는 과정을 말함

`API(Application Programming Interface)`

클라이언트가 서버와 통신하기 위한 인터페이스

API 종류: REST API(가장 흔한 방식), GraphQL

`REST API`: 주소로서 데이터를 구분하는 API 설계 방식

![image.png](attachment:ef6e02ff-33a0-4636-91f6-9119d969dc0f:image.png)

REST API는 이러한 주소체계를 활용하여서 데이터를 구분,
클라이언트는 이러한 주소를 이용하여 데이터를 요청할 때 내부적으로 HTTP 통신을 하게 됨

`HTTP(S) 통신`
리액트에서는 HTTP(S) 기반으로 통신이 이루어지며, HTTP(S)는 내부적으로 메서드를 활용하여 데이터 통신의 역할을 구분

`GET`: 데이터 요청할 때 사용

`POST`: 데이터 추가할 때 사용

`PUT/PATCH`: 데이터 수정할 때 사용

`DELETE`: 데이터를 삭제할 때 사용

### fetch-1(basic)

React에서 데이터 통신은 side effect로 취급되어서 side effect를 처리할 때 사용할 수 있는 React 훅 중 하나인 useEffect 훅을 사용할 수 있음

React에서는 fetch 라는 웹에서 제공하는 내장함수가 있어서 fetch함수를 이용해서
REST API로 설계되어져 있는 API주소를 매개변수로 전달하면 그 주소를 기반으로 데이터 통신을 하게 됨

```tsx
import { useEffect, useState } from "react";
interface Posts {
  id: number;
  title: string;
  views: number;
}
export default function Fetch() {
  const [posts, setPosts] = useState<Posts[]>([]); //렌더링용 상태
  //컴포넌트가 생성 될 때 최초로 1회만 API 데이터 통신을 하는 코드를 이렇게 추가
  useEffect(() => {
    fetch("http://localhost:3000/posts") //데이터 통신의 결과를 받아주는 then 메소드
      .then((response) => {
        return response.json();
      })
      .then((data) => setPosts(data)); //fetch해와서 posts에 저장
  }, []);
  return (
    <>
      <h3>Fetch</h3>
      <ul>
        {posts.map((post) => (
          <li key={post.id}>{post.title}</li>
        ))}
      </ul>
    </>
  );
}
```

### fetch-2 (loading)

렌더링 된 데이터를 새로고침 해보면 깜빡거림 문제 발생

이유: 실제로 컴포넌트가 화면에 그려지고 난 다음에 useEffect의 이펙트 함수가 실행되게 되고 이펙트 함수 내부에서 실행되는 패치 API조차 비동기로 동작하기 때문에 실제로 데이터를 요청하고 요청 받은 데이터를 응답 받고
응답 받는 데이터를 상태에 세팅하기까지 찰나의 시간에 텀이 있기 때문

그래서 서버에서 응답이 지연되었을때를 가정할 수 있는 코드적인 처리가 필요함

```tsx
import { useEffect, useState } from "react";
interface Posts {
  id: number;
  title: string;
  views: number;
}
export default function Fetch() {
  const [posts, setPosts] = useState<Posts[]>([]);
  const [isLoading, setIsLoading] = useState(false);
  useEffect(() => {
    setIsLoading(true); //데이터 통신 전에 true로 바꿔주기
    fetch("http://localhost:3000/posts")
      .then((response) => {
        return response.json();
      })
      .then((data) => setPosts(data))
      .finally(() => {
        setIsLoading(false); //데이터 통신 후에 false로 바꾸기
      });
  }, []);

  return (
    <>
      <h3>Fetch</h3>
      <ul>
        {isLoading ? ( //데이터가 다 불러와져야 데이터 보여주기
          <p>Loading... </p>
        ) : (
          posts.map((post) => <li key={post.id}>{post.title}</li>)
        )}
      </ul>
    </>
  );
}
```

### fetch-3 (error)

데이터 통신에서 2가지 종류의 에러

1. 도메인은 존재하지만 그 도메인에 해당되는 API 자원이 없는 경우
2. 도메인 자체가 완전히 틀려버린 경우

404의 경우 response 객체까지는 들어오는데 ok 라는 속성(정상적으로 데이터를 받았냐) 이 false로 들어옴

그래서 404는 response 객체에서 받아주기

```tsx
import { useEffect, useState } from "react";
interface Posts {
  id: number;
  title: string;
  views: number;
}
export default function Fetch() {
  const [posts, setPosts] = useState<Posts[]>([]);
  const [isLoading, setIsLoading] = useState(false);
  const [error, setError] = useState(""); //에러 상태값
  useEffect(() => {
    setIsLoading(true);
    setError("");
    fetch("http://localhost:3000/posts2")
      .then((response) => {
        if (!response.ok) throw new Error("네트워크 통신 오류"); //404이면 네트워크 통신 오류 경고문
        return response.json();
      })
      .then((data) => setPosts(data))
      .catch((e) => {
        setError(e instanceof Error ? e.message : "unknown error");
        //이게 에러 인스턴스면 에러 객체의 메시지라는 속성의 값을 값으로 세팅 아니면 unknownError 라는 텍스트를 세팅해라
      })
      .finally(() => {
        setIsLoading(false);
      });
  }, []);

  if (error) return <p>Error: {error}</p>;

  return (
    <>
      <h3>Fetch</h3>
      <ul>
        {isLoading ? (
          <p>Loading... </p>
        ) : (
          posts.map((post) => <li key={post.id}>{post.title}</li>)
        )}
      </ul>
    </>
  );
}
```

3가지 상태 필요

1. 실제 요청한 데이터를 저장할 상태
2. 로딩을 제어할 상태
3. 에러를 제어할 상태

### fetch-4 (signal)

데이터 요청을 취소하는 기능

```tsx
import { useEffect, useState } from "react";
interface Posts {
  id: number;
  title: string;
  views: number;
}
export default function Fetch() {
  const [posts, setPosts] = useState<Posts[]>([]);
  const [isLoading, setIsLoading] = useState(false);
  const [error, setError] = useState("");
  useEffect(() => {
    const controller = new AbortController(); //생성자 함수로 인스턴스 객체를 만들기
    setIsLoading(true);
    setError("");
    fetch("http://localhost:3000/posts", {
      signal: controller.signal,
    })
      .then((response) => {
        if (!response.ok) throw new Error("네트워크 통신 오류");
        return response.json();
      })
      .then((data) => setPosts(data))
      .catch((e) => {
        if (e instanceof Error && e.name !== "AbortError") setError(e.message);
      })
      .finally(() => {
        if (!controller.signal.aborted) setIsLoading(false);
      });

    return () => controller.abort(); //요청 취소 메서드
  }, []);

  if (error) return <p>Error: {error}</p>;

  return (
    <>
      <h3>Fetch</h3>
      <ul>
        {isLoading ? (
          <p>Loading... </p>
        ) : (
          posts.map((post) => <li key={post.id}>{post.title}</li>)
        )}
      </ul>
    </>
  );
}
```

### fetch-5 (async)

데이터 통신에서 promise-then 방식을 사용하지 않고 async/await 방식을 사용하고 싶은 경우

useEffect 훅 자체의 이펙트 함수는 async로 지정할 수 없게 설계되어 있어서 그냥 async로만 바꾸는거는 불가능하지만 이펙트 함수 내부에서 async로 정의되어 있는 함수를 새롭게 재정의하는 것은 가능함

async/await 방식에서는 에러처리를 try-catch로 함

```tsx
import { useEffect, useState } from "react";
interface Posts {
  id: number;
  title: string;
  views: number;
}
export default function Fetch() {
  const [posts, setPosts] = useState<Posts[]>([]);
  const [isLoading, setIsLoading] = useState(false);
  const [error, setError] = useState("");
  useEffect(() => {
    const controller = new AbortController();
    const fetchPosts = async () => {
      setIsLoading(true);
      setError("");
      try {
        const response = await fetch("http://localhost:3000/posts", {
          signal: controller.signal,
        });
        if (!response.ok) throw new Error("네트워크 통신 오류");
        const data = await response.json();
        setPosts(data);
      } catch (e) {
        if (e instanceof Error && e.name !== "AbortError") setError(e.message);
      } finally {
        if (!controller.signal.aborted) setIsLoading(false);
      }
    };

    fetchPosts();

    return () => controller.abort();
  }, []);

  if (error) return <p>Error: {error}</p>;

  return (
    <>
      <h3>Fetch</h3>
      <ul>
        {isLoading ? (
          <p>Loading... </p>
        ) : (
          posts.map((post) => <li key={post.id}>{post.title}</li>)
        )}
      </ul>
    </>
  );
}
```

### fetch-crud

export default function FetchCrud() {

        title: "a modify title",
        views: 155,
      }),
    });
    const data = await response.json();
    console.log(data);
  };

    const response = await fetch("http://localhost:3000/posts/1", {

        "Content-Type": "application/json",

      body: JSON.stringify({
        title: "a patch title",
      }),

### axios-total

axios를 이용한 로딩 상태, 에러 상태, 데이터 요청 취소 구현

```tsx
import { useEffect, useState } from "react";
import axios from "axios";
interface Posts {
  id: number;
  title: string;
  views: number;
}
export default function Axios() {
  const [posts, setPosts] = useState<Posts[]>([]);
  const [isLoading, setIsLoading] = useState(false);
  const [error, setError] = useState("");
  useEffect(() => {
    const controller = new AbortController();

          signal: controller.signal,

      }
    };

    axiosPosts();

  }, []);

  if (error) return <p>Error: {error}</p>;

  return (
    <>
      <h3>Axios</h3>
      <ul>
        {isLoading ? (
          <p>Loading... </p>
        ) : (
          posts.map((post) => <li key={post.id}>{post.title}</li>)
        )}
      </ul>
    </>
  );
}
```
