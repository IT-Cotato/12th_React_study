### useId

```tsx
<div>
  <input type="checkbox" id="apple" />
  <label htmlFor="apple">사과</label>
</div>
```

⇒ 체크 박스 옆에 있는 글씨를 눌러도 체크 표시가 가능하게 만드는 htmlFor 속성이 있다. 같은 id 값을 제공해주면 된다.

![image.png](attachment:fdee2add-d7f5-43cd-bd20-7c34e34222b7:image.png)

그러나 렌더링 시 두번째 사과 체크박스는 굴씨를 눌러도 체크박스가 동작하지 않는데, 이는 같은 id 값을 사용했기 때문이다.

이를 위해 react 18에서는 useId 훅을 사용한다.

```tsx
export default fuction Checkbox() {
	const uuid = useId();
	return(
		<div>
			<input type="checkbox" id="apple"/>
			<label htmlFor={uuid}>사과</label>
		</div>
	);
}
```

⇒ 사용 예시 uuid는 항상 고유한 값을 갖는다.

### useEffect

useEffect(effect함수, 의존성배열([]))

의존성 배열이 호출 되는 경우는

1. 컴포넌트가 생설 될 때(마운트)
2. 컴포넌트가 삭제 될 때(언마운트)
3. 컴포넌트가 변경 되었을 때(업데이트)

이 세가지 상황이다.

⇒ 의존성 배열은 비어있을경우 마운트 될 때만 호출된다.

컴포넌트가 삭제 될 때만 호출하고 싶다면 effect 함수의 callback 함수 내부에 return으로 호출하면 된다.

그리고 컴포넌트가 변경 시 호출되게 하려면 의존성 배열을 채워주면 된다.

```tsx
useEffect(() => {
  console.log("Count Change :" + count);
}, [count]);
```

⇒ 예시 코드

**main.tsx에 존재하는 StrickMode는 활성화 시에 내부적으로는 생성 삭제 생성이라는 과정을 반복한다.**

**⇒ 잠재적인 컴포넌트 에러를 발견하기 위해서**

### Todo

새로고침을 해도 값을 유지하는 법

```tsx
const [todos, setTodos] = useState<Todo[]>(
  JSON.parse(localStorage.getItem("todos") || "[]")
);

useEffect(() => {
  localStorage.setItem("todos", JSON.stringify(todos));

```

⇒ 로컬 스토리지를 이용한 todos 저장 방식이다. 이러한 경우 localstorage에서 저장된 값을 가져오는데 새로고침을 해도 리스트가 사라지지 않는다.

### 컴포넌트 리렌더링 조건

1. 상태가 변경되었을때
2. props가 변경되었을 때
3. 부모 컴포넌트가 리렌더링 되었을 때

불필요한 리렌더링을 막기 위해서는 React.memo를 사용하는 것이다.

컴포넌트 함수를 다시 실행하지 않고 이전에 렌더링된 결과를 그대로 반환하는 방식이다.

이를 통해 변경되지 않은 자식 렌더링을 막을 수 있고 리액트 성능에 큰 영향을 끼친다.

![image.png](attachment:f61c6f88-db97-4502-b19d-d47436ad43bc:image.png)

```tsx
export default React.memo(function Child() {
  console.log("childA");
  return (
    <>
      <h1>ChildA Component</h1>
      <ChildB />
    </>
  );
});
```

⇒ 다음은 예제 코드이다. (메모이제이션 방식)

그러나 React.memo 를 사용하고 있는 상태가 변경된다거나 props가 바뀔 경우는 렌더링을 막을 수 없다.

### useCallback

함수의 참조형이 바뀌면 컴포넌트는 계속해서 리렌더링 된다.

이때 useCallback을 사용하는데

```tsx
export default function App() {
	console.log("App");
	const [count, setCount] = useState(0);
	const increment = useCallback(() => {
		setCOunt((count) => count +1);

	}, []);
	return (
		<>
			<h1>count: {count}</h1>
			<button onClick{() => setCount((count => count + 1)}>증가</button>
			<ChildA increment={increment} />
		</>
	)
}
```

⇒ 다음은 함수 참조형이 바뀌어도 리렌더링을 막는 useCallback의 예시 코드이다.

useCallback은 increment를 메모이제이션 하기 때문에 의존성 배열의 값이 직접적으로 변경된 것이 아니라면 항상 메모리에 저장된 increment값을 가져와 쓴다.

### useMemo

```tsx
import { useState } from "react";

const initialItems = new Array(29_999_999).fill(0).map((_, i) => {
  return {
    id: i,
    selected: i === 29_999_998,
  };
});

export default function App() {
  const [count, setCount] = useState(0);

  // 불필요한 연산을 만들어준 것
  // 3000만개의 배열 데이터를 렌더링 마다 재생성하고 있음
  const selectItems = initialItems.find((item) => item.selected);
  return (
    <>
      <h1>Count: {count}</h1>
      <button onClick={() => setCount((prevCount) => prevCount + 1)}>
        증가
      </button>
      <p>{selectItems?.id}</p>
    </>
  );
}
```

⇒ 해당 코드는 리렌더링 할때마다 무수히 많은 연산비용이 발생하는 코드이다.

불필요한 리렌더링을 막기 위해서는 useMemo를 사용할 수 있는데,

```tsx
const selectItems = useMemo(
	() => initialItems.find((item => item.selected),
	[count]
);
```

⇒ 이 코드의 경우 새로운 컴포넌트가 생성될 때만 리렌더링이 발생한다.

### Lazy

```tsx
import ChildA from "./components/ChildA";
import ChildB from "./components/ChildB";

export default function App() {
  return (
    <>
      <ChildA />
      <ChildB />
    </>
  );
}
```

⇒ JSX에 포함되어 있고 정적인 import 문을 통해 로드되는 컴포넌트는 화면에 보이지 않더라도 초기 번에들에 포함되어 항상 다운로드 된다. 이 문제를 해결하기 위해 React.lazy를 사용한다.(비동기적 로딩)

```tsx
const ChildA = React.lazy(() => import("./components/ChildA"));
```

⇒ 필요할 때 다운로드 실행

하지만 해당 방법은 렌더링 될 때 그제서야 다운로드를 받기 때문에 컴포넌트 최초 렌더링 시간이 길어질 수 있다.

이를 처리할 수 있는 suspense 내장 컴포넌트가 있다.

```tsx
import { lazy, useState } from "react";
const ChildA = lazy(() => import("./components/ChildA"));
const ChildB = lazy(() => import("./components/ChildB"));

export default function App() {
  const [isShow, setIsShow] = useState(false);
  return (
    <>
      <button onClick={() => setIsShow((isShow) => !isShow)}>토글</button>
      {isShow && (
        <>
          <suspense fallback={<h1>ChildA Loading..</h1>}>
            <ChildA />
          </suspense>
          <ChildB />
        </>
      )}
    </>
  );
}
```

⇒ fallback에 있는 내용을 로딩시간동안 표시

### error-boundary

리액트는 컴포넌트 렌더링 과정에서 발생하는 오류를 심각하게 생각한다.

예전엔 componentDidCatch와 getDerivedStateFormError를 같이 사용해 이를 해결했지만, 요즘에는 react-error-boundary와 같은 외부 패치지를 사용해 에러 바운더리를 적용한다.

```tsx
npm install react-error-boundary
```

⇒ 설치 코드

```tsx
import { lazy, useState } from "react";
const ChildA = lazy(() => import("./components/ChildA"));
const ChildB = lazy(() => import("./components/ChildB"));

export default function App() {
  const [isShow, setIsShow] = useState(false);
  return (
    <>
      <button onClick={() => setIsShow((isShow) => !isShow)}>토글</button>
      {isShow && (
        <>
	        <suspense fallback={<h1>ChildA Loading..</h1>}>
          <ChildA />
          </suspense>

          <ErrorBoundary fallback={<div>Something went wrong</div>}
          <suspense fallback={<h1>ChildA Loading..</h1>}>
          <ChildB />
          </suspense>
          </ErrorBoundary>
        </>
      )}
    </>
  );
}

```

더 디테일하게 에러를 처리하고 싶다면

```tsx
function Fallback({
	error,
	resetErrorBoundary: () => void;
}: {
	error: Error:
	resetErrorBoundary: () => void;
}) {
	return (
		<div role="alert">
			<p>something went wrong:</p>
			<pre style={{ color: red}}>{error.message}</pre>
			<button onClick={resetErrorBoundary}>retry</button>
			</div>
	);

}
```

⇒ 이와 같이 객체 형태를 통해 더 세밀하게 에러를 관리할 수 있다.
